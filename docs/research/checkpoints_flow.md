## Write semantics, confirmed in the flows

- `QFT_ModifyQuestInt`:
  - With no `ModifierOperator`, it is a **SET**. This applies to DeathQuest_Beat and QuestBeat.
  - `EQuestIntModifyOperator::ADD` adds. It is used for SealsBroken, StandStoneInt, NotFoundStones and Shard_Amount.
- `QFT_UpdateQuestLocation`: `Revealed:true` sets the location true. Without `Revealed`, it sets it false.
- Bools and locations are only appended to the save the first time something writes them. The GuestChar sample confirms this.
- `TestQuestInt` with no `TestValue` tests for 0, and an absent int reads as 0.
- No flow ever writes `QuestTrackedMain` or `QuestTracked`. The engine manages them.

## Withering Heights: node-by-node writes

### Beat 4 (`QF_DeathQuest_Beat4`)

All of these nodes are fired by interacting with a **world actor**: a standing stone, a seal, or a trigger volume.

**ReachedStandStones** (volume; requires DeathQuest_Beat==4 and HasTriggeredSSVol false):
- HasTriggeredSSVol=true
- objective `ReachedStandingStones`
- StandingStonesArea=false
- StandStoneVillage, StandStoneWaterfall and StandStoneFortress = true

**StandingStones.{Emberwood|SilverThornLodge|Waterfall}Stone** (stone interaction):
- Sets the matching `*StoneDone`=true and hides that StandStone* location.
- At Beat 4, StandStoneInt ADD 1, which gives objective `InteractedWithStone1`, then `InteractedWithStone2`.
- At the third stone (StandStoneInt==2):
  - objective `BreakTheThreeSeals`
  - InvestigatedStandingStones=true
  - VillageArea, FortressArea and FallArea = true
- StandStoneInt **stays at 2**. The save matches this.

**Seals.{Waterfall|Silverthorn|Emberwood}** (seal interaction, at Beat 4, when the seal's bool is false):
- GiveItemToPlayer of the seal's key: `ITEM_Resources_SealBreakKey_Fall`, `_Fort` or `_Vil`.
- `<X>SealBroken`=true, where X is Waterfall, Silverthorn or Emberwood.
- SealsBroken ADD 1, plus the seal VFX.
- Then it branches on the new count:
  - **SealsBroken==1:** objective `BreakRemainingtwoSeals`, and that seal's area (FallArea, FortressArea or VillageArea) is set false.
  - **SealsBroken==2:** objective `BreakTheFinalSeal`, and that seal's area is set false.
  - **SealsBroken>=3:** this is the **target checkpoint**:
    - objective **`ChallangeImaru`** (the misspelling is in the data)
    - **DeathQuest_Beat SET 5**
    - **SlayImaruTarget=true**
    - that seal's area set false
    - prompt "Your soul resonates with Imaru's grief. You are ready to bring the fight to her."
- At Beat 5, an already-broken seal hands its key back if you don't have it. This happens in Blank_C_14, Blank_C_16 and Blank_C_18.

### Beat 5 (`QF_DeathQuest_Beat5`)

**ImarusLair** (lair door interaction):
- Requires all three keys: TakeItem SealBreakKey_Fall, then _Fort, then _Vil.
- Then `TriggerBreakSeal` on the door, which changes world state.
- **No quest variables are written.**

**RecievedImaruHead:**
- **Trigger:** this is not the boss's death. It is the `DT_Progression_Quests` row `ImaruHead`, "ALL ITEMS[Imaru's Head]" of type ItemsPickedUp, which fires this entry.
- **Conditions:** QuestState Given, HasRecievedImaruHead false, and DeathQuest_Beat==5. Beats 0–4 link to SkipToBeat5 instead, which repairs the state.
- **Writes:**
  - objective **`ReturnToDeath`**
  - DeathTempleTarget=true
  - SlayImaruTarget=false
  - NPCDeath=false
  - **ImaruDefeated=true**
  - **HasRecievedImaruHead=true**

**DeathBeat5Entry** (Death dialogue):
- When ImaruDefeated is false, Death only gives hint lines.
- When ImaruDefeated is true, the player has the head, and there is space for the pack:
  - TakeItem `ITEM_Resources_Imaru_Head`
  - GiveItem `ITEM_Consumable_DeathquestRewardPack` (rCw_tULBJw2cbgiNTYjmuQ)
  - GiveCraftingRecipe `RECIPE_Masterworks_Shield_Dragonfire_Imaru` (V6JWS0Q-GuvrJS2f3-c_DA)
  - **CompleteQuest**, which sets QuestState to 2
  - DeathTempleTarget=false
  - NPCDeath=true
  - then a link to `BlackKnightsFortress.InitiateDRQuest`
- **No WH bools are written here.**

### Death post-quest dialogue (`QF_Death_PostQuestDialogue`)

**InitiateDRQuest**, reached through QF_Death → PostQuestEntry when RecievedDRQuestFromDeath is false.

At BKF QuestBeat==0:
- GiveQuest, only if BKF is not already Given
- BKF GivenQuestOnLogin=true
- objective `DR_Main_Objective_0`
- DR_MQ_Cathan=true
- RecievedDRQuestFromDeath=true
- DR_MQ_Death=false

At QuestBeat 1–4, Death swaps Imaru's Head for `ITEM_Resources_Visage_Dragon_Imaru`. That branch only runs if the player still has the head.

### Catch-up

`QuestCatchupConfigs`: when WH is Complete and BKF is Ungiven, the game runs `AutoGiveDRMainQuest`, which does the following:
- GiveQuest
- objective `DR_Main_Objective_-1`
- DR_MQ_Death=true
- GivenQuestOnLogin=true

### Other bool writers outside the Beat flows

- **`QF_EmberwoodVillagePuzzle`** writes SpokenToShady, SpokenToSuspicious, SpokenToSnickering, LearnedCrime, LearnedMotive and ArmadylStatueSpokenTo. These are pre-seal puzzle dialogue.
- **`QF_Death_OptionalDialogue`** writes AskedAbout* and LearnedAboutFragments.
- **Every bool in the live WH record is traced to a write node.**

### For the game to continue correctly from the checkpoint

- WH QuestState must be 1 (Given), DeathQuest_Beat must be **5**, and HasRecievedImaruHead must be false or absent. The objective string is `ChallangeImaru`. It is cosmetic, because no flow tests it.
- The three curse fragments must be in the inventory to open the lair door. If they are missing, the player can re-obtain them by interacting with each broken seal at Beat 5.
- Imaru's Head must **not** be in ItemsPickedUp, so that picking it up fires the ImaruHead progression row again. This is inferred: no "progression unlocked" list exists anywhere in the save.
- **World side:** Imaru must be alive in the world. The reference player's worlds list `ai_boss_imaru` in DefeatedBossesInternalNames, and the lair door is world state too. The character checkpoint is exact, but the fight is only replayable in a world where Imaru is alive.

### Answers to the coordinator, reconciled with imaru_world.md

These agree with imaru_world.md.

1. **Beat and objective.**
   - DeathQuest_Beat is **5**. The third-seal branch SETs it; Beat 4 is the value before that seal.
   - The objective is **`ChallangeImaru`**.
2. **Seal keys.**
   - All three keys are **required** for the lair door, one of each:
     - Rage: `TQY6cUXdLjzqCIuXB3vAvw`
     - Despair: `ObT03UmkX-U-WJ667Rk0vA`
     - Grief: `o9Nec0TWzFiYJIeiYQBjVw`
   - If they are missing, the player can get each one back from its broken seal at Beat 5.
3. **Imaru's Head in ItemsPickedUp.**
   - **Remove** `ALQSs0j7loBVpum0CaDH2w` from ItemsPickedUp.
   - The trigger is the progression row `ImaruHead` (type ItemsPickedUp).
   - The save has no list of unlocked progression rows, so a row can only count as unlocked through ItemsPickedUp. That makes it first-pickup-only by inference; the engine code is not in the dump to confirm it.
   - Removing the ID is harmless, because the game re-adds it when the head is picked up.
4. **Other gates: none.**
   - DT_Progression_Quests uses only ItemsPickedUp (49 rows) and ActorsInteractedWith (1 row: the cleansing pool, at Beat 3).
   - No WH flow tests KilledOnceAIs, PlayerHooksTriggered or the Journal.
   - Removing the recipe, journal entry, pack and shield is optional cleanup.
