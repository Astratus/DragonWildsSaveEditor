# Early group checkpoints: First Steps through Dragon Slayer

The JSON is in `checkpoints_early.json`. It was generated by `(working file, not included)`. The flow dumps are in `(working file, not included)`, and the world copies are in `early_work\worlds\`. Everything was read-only.

## Tutorial quests (First Steps, Getting Started, Ratcatcher, Rune Mysteries): no checkpoints

- **How these quests advance:**
  - `QF_FTUE_*` chain the quests with silent GiveQuest/CompleteQuest calls inside NPC dialogue: Zanik, Vannaka and the WOM.
  - They also use temple entry/exit trigger volumes (`TempleTriggerEntry/Exit`).
  - Several steps fire on first pickups (`DT_Progression_Quests` rows StoneAxe, RuneEssence, AirRune, AstralRune and Flax), and all of those items have long been in ItemsPickedUp.
- **Which records are already complete:** First Steps is complete. Its related records AmuXOUitB08PYDCmdVA_Ug, v9LCTEjS and 7i8X403L are present or absent as in the v83 and live saves (only AmuX… exists). The Rune Mysteries rows zrqq… and TgVn… are complete; EWRW… is absent.
- **Dragon Slayer is coupled to the tutorial:** its Beat 1 bools are written by the FTUE flows (WOMTempleHidden, HasCompletedFTUE).
- **Why not offer them:** reverting into the tutorial would rely on starting-area triggers and first-pickup rows that can't fire again. Even a "complete / next not started" boundary adds nothing, because each tutorial quest silently starts the next one.
- **Recommendation:** offer nothing here.

### What happens after the horn is crafted

1. **Picking up the crafted Challenge Horn** fires the `DT_Progression_Quests` row ChallengeHorn (type ItemsPickedUp), which runs **Beat4 RecievedChallengeHorn**. At QuestBeat 4 it writes:
   - objective "Challenge Velgar"
   - BloodblightRuin and HighlandsArea = false
   - DragonsLairChallengeVelgar = true
   - CompletedBeat4 = true
   - QuestBeat SET 5
   - HasSummonHornRecipe, plus the horn recipes
2. **Beat5 SummonAltar** (the Dragonkin Altar, BP_BossAltar_Region1, whose SummonItem is the horn):
   - It checks only that the horn is in the inventory. No quest variable is tested.
   - It takes the horn, then calls `QFT_TriggerBossAltarSummonBoss`.
3. **The kill.** Loot row `DragonVelgar` drops Velgar's Head:
   - drop chance 100%
   - added to the inventory automatically
   - one instance per player, only for players who dealt damage
4. **Picking up the head** fires the progression row VelgarHead, which runs **Beat5 PickedUpVelgarHead**. This is the only writer of HasEverRecievedDragonHead. It writes:
   - objective "Return to the Wise old man after killing velgar"
   - DragonsLairChallengeVelgar = false
   - WiseOldMan = false
   - WiseOldManObjective_Lair = true
5. **WOMBeat5Entry** runs when the player has the head and a free slot:
   - takes the head
   - gives the Beat5 reward pack and the Dragonfire shield recipe
   - **CompleteQuest**
   - WiseOldMan = true, WiseOldManObjectiveDS = false
   - **GiveQuest Withering Heights** (objective TalkToWomNEGF, WomGFExitTarget = true)
   - It writes no Dragon Slayer bool and doesn't change the objective, which matches the completed live record.
6. **Withering Heights Beat1** later writes the Dragon Slayer bool `WoMAshiensWatch`, without a NewValue, so it is false.

### Variables removed from the live record

- **HasEverRecievedDragonHead:** written by PickedUpVelgarHead. It is removed only for ds_ready_challenge_velgar.
- **WoMAshiensWatch:** written by Withering Heights Beat1.
- **FoundDragonTooth:** in the live list it comes after WoMAshiensWatch, and Dragon Tooth is ItemsPickedUp[355], after Horn[263] and Head[264]. So it was first written after Dragon Slayer was complete.
  - The flows read it only at Beat 3 and Beat 4, so leaving it out is harmless.
- **Everything else is unchanged.** All other bools were set before the horn. For example, HasSpokeToCathan = false comes from Beat3 SetQuestBool_C_4, which has no NewValue.

### Why ds_investigate_castle is rated med

- It is the real v83 record: 11 bools, which also matches the public Early Access sample.
- But the next step, `CastlePieceFound`, is fired from outside the Dragon Slayer flows, and the trigger was not found in the dump.
- `HasAntiDragShieldRecipe` comes from a side flow, QF_MasterworkStatues.
- Four first-pickup rows would have to be cleared: Sap, Tooth, Horn and Head.
