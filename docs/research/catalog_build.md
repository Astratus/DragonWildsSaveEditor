# Catalog built from the installed game (`gamedata/` + `catalog.py`)

The editor ships its own item and unlock-name catalog in `dragonwilds_save_editor/data/catalog/` (`items.json`, `unlock_names.json`, `build_info.json`). It is generated by our own code from an **installed copy of RuneScape: Dragonwilds**: the `dragonwilds_save_editor/gamedata/` package reads the game's IoStore containers (read only), and the classification rules in `catalog.py` turn the values it reads into catalog entries. `packaging/build_catalog.py --game-dir <install>` regenerates the bundled copy (deterministic output). The bundled copy was built from game version **1.0.2.2**.

The same build runs on the player's machine on request (**Help > Update item catalog**, `dwsave catalog build`), from the player's own installation, with no network connection. It checks itself before anything is written; a passing user-built catalog is then used instead of the bundled one until **Reset to bundled catalog**.

History: earlier curated copies were compiled from catalogs with no licence (OogaBoogaCode/RSDWSaveEditor, RSDWTools) and were removed. Then, up to the 0.1.0 pre-release work, the catalog was generated from the game's asset JSON in the public RSDWArchive dump (build 1.0.2.0); the editor could download a slice of that dump. Both the dump path and all network code have been removed. The dump-based catalog is now used only for cross-checking (see [Cross-check](#cross-check-against-the-earlier-dump-based-catalog)). The file-format sources and what was inferred are in [gamedata_provenance.md](gamedata_provenance.md).

## Reading the game

| Step | Where | What |
|---|---|---|
| Find the install | `gamedata/install.py` | Steam libraries (`libraryfolders.vdf`, `steamapps/common/*Dragonwilds*`), the absolute paths the game writes into its own logs (`%LOCALAPPDATA%\RSDragonwilds\Saved\Logs\*.log`), common folders on fixed drives; the GUI falls back to a folder picker. A folder counts when `RSDragonwilds/Content/Paks` holds `RSDragonwilds-Windows.utoc` and `global.utoc`. The path is never recorded. |
| Containers | `gamedata/iostore.py` | `RSDragonwilds-Windows.utoc/.ucas` (TOC v8: chunk ids, offsets/lengths, compression blocks, directory index: 125,297 entries, 106,285 paths) and `global.utoc` (the script-object table: 62,376 native objects). The game ships them unencrypted and uncompressed. The pak `RSDragonwilds-Windows.pak` is read only for `Config/DefaultGame.ini` (`ProjectVersion`, recorded as `game_version`). |
| Packages | `gamedata/zen.py`, `game.py` | Zen package headers (UE 5.6 layout): name map, imports, exports; an export's class resolves through the script-object table (`/Script/Dominion.ItemData`) or, for Blueprint classes, through the imported package up to the first native class. |
| Properties | `gamedata/uprops.py`, `decode.py`, `schemas.py` | Unversioned property headers say which property indices are present, not their types. The types come from `data/gamedata/schemas.json`, our inferred byte layouts of the native classes (see [gamedata_provenance.md](gamedata_provenance.md#native-class-schemas)). |
| Text | `gamedata/stringtable.py` | FText values point into the game's string tables (`ST_ItemNames` and others: 61 tables read), which are decoded directly. |
| Derivation | `gamedata/derive.py` + `catalog.py` | Field positions (which index is the name, stack size, ...) and the classification rules below. |

**Which assets** (`catalog.is_needed`, on container paths; never `/Art/` or `/Audio/`): 5,671 packages.

| Kind | Assets |
|---|---|
| Items | `ITEM_*` (not `*_MeshData_*`), `DA_Consumab*` (plans, patterns/vestiges, mount unlockers; the game spells one of them `DA_Consumabe_`) |
| Recipes | `RECIPE_*`, `DA_Recipe*` |
| Building pieces | `BUILDPIECE_*`, and `DA_T<n>*`, `DA_BaseBuilding*`, `DA_FarmPlot*`, `DA_BuildPiece*` under `/Gameplay/`; never `*DerivedData*` |
| Player hooks | `PH_*` and `BP_*` in `/PlayerHooks/` |
| Spells | `USD_*` (UtilitySpellData) |
| Journal | `JOURNAL_*` |
| Killed-once AIs | `BP_*_Data*` under `/Gameplay/AI/`, plus `DA_AI_Data` |
| Skill perks | `PerkV2_*` |
| Skills | `SKILL_*` |

**Decoding.** 5,094 of the 5,671 main exports (90 %) decode completely with their class schema; every one of them ends exactly at the end of its export. The other 577 belong to classes the schema inference could not solve completely (17 classes, e.g. `RangedAmmoData`, `TrinketItemData`, `UtilitySpellData`, some player-hook and journal classes) and use fallbacks:

- **PersistenceID** located by pattern: a 22-character base64url FString followed by the InternalName FString (or, in a Blueprint class default object, the last value of the export).
- **Suffix alignment**: the inherited part (the ItemData fields, the journal-entry base) is decoded by trying every start offset and keeping the one whose parse lands exactly on the PersistenceID. Up to two inherited indices with no known type are tried with plain types, and the choice must fit every instance of the class (208 items decoded this way).
- **Pattern scans** for FText values (string-table entries, base texts) and DataTable row handles (AI row names, checked against the name maps of the game's `DT_AIData*` tables).

## Self-check

`catalog.self_check()` runs on every build from the game (user-side and bundled); if it reports a problem, nothing is written and the current catalog stays in use:

- at least 80 % of the catalog's game assets fully decoded by their class schema (a game patch that changes a native class shows up here), at most 1 % unreadable;
- every item and every unlock has a unique, valid 22-character PersistenceID and a name; every item has a known inventory tab and a stack size of at least 1;
- plausible counts: minimum per section (items 1,500, recipes 1,000, journal 1,000, buildings 600, perks 120, AIs 100, spells 30, hooks 30, skills 10), and against the catalog in use at most 3x its size per section and at least 90 % of its IDs found again.

## Derivation rules

**IDs.** Every item and unlock ID is the asset's own PersistenceID, the 22-character base64url string the save stores (in `ItemData`, `RecipesUnlocked`, ...). The "main" export is the one named like the file, or its class default object `Default__<file>_C`.

Item field positions (ItemData indices; a subclass shifts them by its number of own properties): name 1 (FText), max stack 12, category tag 17, filter tags 20, base durability 25, PersistenceID 36, InternalName 37, bSoftDeleted 38.

- **name**: the name FText (culture-invariant string, base source string, or string-table entry). If there is none, the InternalName title-cased and `derived_name = true`.
- **placeholder_name**: the name starts with `[PH]`. The prefix is stripped.
- **category**: from the export class:
  - `ItemData` -> Resource; `WearableEquipmentData` -> Armour
  - `HeldEquipmentData`, `FishingRod…`, `HarvestTool…`, `HeldContainer…`, `SpadeTool…` -> Weapon/Tool
  - `ShieldData` -> Shield; `TrinketItemData` -> Jewellery
  - `RangedAmmoData`, `FishingBaitAmmoData`, `MagicAmmoData` -> Ammo
  - `SeedHeldEquipmentData`, `HeldTreeSeedData` -> Seed; `FuelItemData` -> Fuel; `WhetstoneItemData` -> Whetstone
  - `JournalItemData` -> Other; `ConsumableMountUnlocker` -> Mount
  - `BP_Consumables_{Food,Drink,Potion,ItemEmitter,SkillTome,Plan_Base,RecipeUnlocker2}_C` -> Food, Drink, Potion, Pack, Tome, Plan, Pattern
- **max_stack**: the max stack size; if absent, 1 (the engine default).
- **max_durability**: the base durability when it is > 0, else null.
- **inv_tab**: from the item's own tags, first match wins:
  1. filter tags contain `ItemFilter.Type.QuestItem` -> `quest`
  2. any tag (filter or category) starts with `ItemFilter.Type.Equipment.Ammo.Rune` -> `rune`
  3. category starts with `Item.Equipment.Ammo.Arrow` / `.Bolt` -> `ammo`
  4. otherwise `bag` (fishing bait is `bag`, as in the save).
- **retired**: bSoftDeleted; or a folder named `Deleted`, `DeletedEntries`, `Depreciated` or `Deprecated`; or a folder or file name with a `Test`/`TEST` word.
- **hint**: only when two or more items share a display name: the asset name without `ITEM_`/`DA_Consumable_`, humanized.
- **source**: the game package path, e.g. `/Game/Gameplay/Items/Consumables/Magic/ITEM_Consumable_Potion_Focused_T3_Construction` (plugin content: `/<Plugin>/...`). Never a disk path.

**Unlock names**: `{section: {id: {name, group, source, asset, ...}}}`. Field positions are relative to the class's PersistenceID index K.

| Section | name | group | extras |
|---|---|---|---|
| RecipesUnlocked | output item's name (items-created array, K-20), else the asset name | crafting skill (K-11, `SKILL_Artisan` -> Artisan); `Vendor/<skill>` under vendor folders | `output_item`, `vestige` (the pattern whose recipe list names it), `retired` |
| BuildingsUnlocked | display name (K-21), else the asset name (CamelCase split) | folders below `BuildingPieces/` | `retired` |
| SpellsUnlocked | spell display name (index 0), else the asset name | skill from the `T_Icon_Tag_Skill_<X>` icon the asset references | `internal` |
| JournalEntries | entry name (K-5; sub-categories: last FText found), else the asset name | folders below `Entries/` | |
| KilledOnceAIs | first FText of the AI data, else the asset name without `BP_AI_`/`_Data` | first folder below `Gameplay/AI/` | `ai_row` |
| PlayerHooksTriggered | asset name without `PH_` | `FTUE` under `/FTUE/`, else `PlayerHook` | `internal` |
| SkillPerks (name table) | perk name (K-9) | associated skill (K-4) | `required_level`, `internal`, `retired` |
| Skills (name table) | name (K-19) | `Skill` | `max_level` (K-18), `retired` (the 3 in `DeprecatedSkills/`) |

`SkillPerks` and `Skills` are name tables, not save lists you unlock things in: skill IDs are the `Id` values in `GameProgress.Skills.Skills` (all 12 in `skills.json` match; Defence, Herblore and Thieving are deprecated), and perk IDs show up in the save's `Progress.SpellsNew` badge list (e.g. Iron Secateurs, `cQfN1EsBDwTU16m3eFSDKA`). Perks are kept out of `SpellsUnlocked` on purpose, so the Unlocks tab never offers a perk as a spell.

## Cross-check against the earlier dump-based catalog

The catalog built from the installed game (1.0.2.2) was compared field by field with the catalog generated earlier from the RSDWArchive 1.0.2.0 dump (`python -m dragonwilds_save_editor.catalog compare`):

- **Items:** 1,605 / 1,605 IDs match; name, category, max_stack, max_durability, inv_tab, retired, hint, placeholder_name and derived_name agree on every item.
- **Unlocks:** every ID of every section matches, and every field except `source` agrees. `KilledOnceAIs` has 51 more entries (197 vs 146): AI data assets present in game version 1.0.2.2 but not in the 1.0.2.0 dump.
- `source` changed from `RSDWArchive 1.0.2.0 <asset JSON path>` to the game package path.

The field positions were assigned from the decoded values and validated by this comparison; the dump-based catalog was never an input to the build.

## Coverage history (dump-based catalog vs the old curated files, 2026-11-25)

Kept for reference; these numbers describe the RSDWArchive-based build, which the install-based build reproduces exactly.

- Items: 1,605 built, 1,606 in the old file, 1,605 IDs matched. Only in the old file: the `Bramblemead Cape` pattern (`M3lV70TtklsLma-1TT8h2g`), whose current asset has no PersistenceID.
- `max_stack` and `inv_tab` matched on every item the old file had a value for (the 17 differences were mount unlockers the old file had no value for). The 23 crop seeds' old durability of 23 was wrong (they stack, so they use `Count`). Earth Rune is Ammo (class `MagicAmmoData`), not Resource.
- The 47 name differences were game text vs. invented names (e.g. patterns are "Green Dyad Cape", not "Pattern: Green Dyad Cape"; ReelDowner fish resolve through their string table).
- Unlock names: recipes, buildings, journal, spells and hooks all matched by ID; most name differences were improvements (raw internal names now resolve, "(vendor)" suffixes became `Vendor/...` groups).

## Gaps

- **Journal:** `Zamorakian Warrior Pack` (`zSQy6k3645jYoQOUhVaMkg`) has no `JOURNAL_*` asset with that ID. Its origin is unknown.
- **Items:** the `Bramblemead Cape` pattern (see above).
- **Groups** are skill names and folder paths, not RSDWTools' "Cooking/Crafting/Smithing" labels. The Unlocks tab only displays and filters by group.
- **Not generated by the catalog build:** `lodestones.json`, `map_points.json`, `main_questline.json`, `skills.json` and `xp_table.json`. The map and lodestone IDs, region names and lodestone locations are verified against the installed game with `python -m dragonwilds_save_editor.gamedata.world` (see [map_points.md](map_points.md) and [lodestones.md](lodestones.md)).

## New game patches

Rebuild from the patched install, check the self-check and `compare` output, re-infer schemas if needed, and regenerate the bundled copy; the steps are in [../development.md](../development.md#item-catalog) and [../RELEASING.md](../RELEASING.md#after-a-game-patch-regenerate-the-item-catalog).
